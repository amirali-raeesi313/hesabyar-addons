# عامل‌های هوشمند حساب‌یار (erp_auto_agent)

فاز ۷ نقشه‌راه: چارچوب Agentهای خودمختار که روی هسته‌ی `erp_auto_core` سوار است.
هر عامل رویداد را تشخیص می‌دهد، تصمیم می‌گیرد، اقدام کم‌ریسک را اجرا و اقدام
حساس را به صف تأیید می‌فرستد — و همه‌چیز Audit می‌شود.

## مدل‌ها
| مدل | نقش |
|---|---|
| `erp.auto.agent` | تعریف عامل: نوع، دامنه‌ی مجاز (`allowed_model_ids`)، سقف مبلغ، آستانه اطمینان، کلید خاموش (`active`)، ابزارهای whitelisted |
| `erp.auto.agent.tool` | ابزار مجاز = مدل + متد + سطح ریسک |
| `erp.auto.agent.run` | هر تصمیم/اقدام: دلیل، اطمینان، منبع داده، اقدام، پیوند تأیید، وضعیت، قابل لغو |

## گاردریل‌های الزامی (پرامپت بخش ۲۴ و ۲۵ و ۲۶)
- **دامنه‌ی محدود:** عامل فقط روی مدل‌های `allowed_model_ids` اقدام می‌کند (`_check_scope`).
- **تأیید انسانی برای حساس:** `requires_approval` یا ریسک بالا یا مبلغ > سقف ⇒ `erp.auto.approval` (با تفکیک وظایف).
- **اطمینان پایین ⇒ فقط پیشنهاد:** اطمینان < آستانه ⇒ وضعیت `suggested`، بدون اقدام.
- **Audit کامل:** هر اجرا در `erp.auto.audit.log`.
- **کلید خاموش فوری:** `active=False` عامل را کاملاً متوقف می‌کند.
- **Idempotent:** اجرای مجدد، فعالیت/تأیید/سند تکراری نمی‌سازد.
- **دلیل + منبع داده + اطمینان** روی هر اجرا ثبت می‌شود.
- **LLM اختیاری** (`ai.deepseek.client`)؛ نبودنش عامل را از کار نمی‌اندازد و هرگز عدد نمی‌سازد.

## عامل‌های آماده
| عامل | ورودی | اقدام | حساس؟ |
|---|---|---|---|
| وصول مطالبات | فاکتور فروش معوق | یادآور پیگیری (`mail.activity`) | خیر — اجرا |
| خرید | کالای زیر نقطه سفارش | درخواست تأیید خرید | بله — تأیید |

## اجرا
- دستی: دکمه‌ی «اجرای اکنون» در فرم عامل، یا منوی «هسته اتوماسیون ← عامل‌های هوشمند».
- خودکار: کرون «اجرای عامل‌های هوشمند» (پیش‌فرض خاموش؛ پس از آماده‌بودن فعال کنید).

## تست
```
odoo-bin -d <db> -i erp_auto_agent --test-enable --test-tags /erp_auto_agent --stop-after-init
```

## گام بعدی
افزودن عامل‌های فروش/انبار/خزانه/HR روی همین چارچوب؛ اتصال تصمیم‌ها به `erp.auto.job`
برای اجرای صف‌دار با Retry؛ فعال‌سازی LLM برای رتبه‌بندی اطمینان.
